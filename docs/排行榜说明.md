# 排行榜说明

适用版本1.5.0，工程核查日期2026年10月13日。首页、设置页、页面标题统一“排行榜”；JSON托管格式使用版本2。99关及排序规则沿用，本轮移除排行榜上的累计分数解释文字，不改变实际排序；未重新登录公众平台核查账号或提交隐私配置。

## 计分与使用

- 普通99关按各关最高分之和降序，再按已完成不同关卡数降序、各已通关关卡最佳活动耗时之和升序；三项完全相同成绩并列。重玩只改善该关记录，不重复累计整局分数。
- 最高分与最快耗时分别保存，可以来自不同次通关。活动计时在棋盘游玩时累加，设置等页面和后台暂停；教学、每日题、打卡经验与外观选择不进入普通排行榜。
- 助手给基础分并中断连对；查看有效提示记入使用次数，两项额外通关奖励按手动比例与提示次数调整。查看后关闭不返次数，同条应用不再扣。公式见 [计分与成长系统](计分与成长系统.md)。当前没有购买加分或奖励广告。
- 只有玩过同一个微信小游戏并托管成绩的朋友才有可读数据；榜单可能暂时为空，刚添加的朋友也可能延迟出现。
- 首次查看先阅读并选择隐私授权，再允许朋友互动权限；“暂不开启”仍可离线玩，也可主动重新查看。朋友权限拒绝后，玩家点击“微信设置”才打开设置。
- 网页显示本机真实成绩，不模拟朋友、名次或联机成功。微信版开放域底栏显示本人实际托管状态。

## 工程与数据

`game.json.openDataContext` 为 `open-data`。入口 `index.js`、绘制 `view.js`、格式/排序 `ranking.js` 与串行同步 `sync.js` 均随工程提供，无需自建服务器或 npm 运行依赖。

托管键继续使用 `miaoge_progress_v1`，其中的 `v1` 是保留的兼容键名。JSON使用 `version: 2`，包含 `points`（各普通关卡最高分之和）、`completed`（不同普通通关数，0～99）、`totalTimeMs`（累计最佳活动耗时）与平台格式 `wxgame.score` / `wxgame.update_time`。平台 `score` 使用积分并限制在Int32最大值 `2,147,483,647`；更新时间单位为秒。

读取器兼容旧 JSON 版本 1：保留旧通关数和用时，缺少的积分以零读取，不根据旧耗时伪造分数。开放域按当前排序择优写完整摘要，不合并两个设备的逐关存档。

未确认隐私与朋友授权前，本人提交仅在主域暂存，不读取或写入云数据。授权后开放域先读取本人云成绩、择优后写入；不会在本人读取失败时把云成绩当零盲写。

读取失败不假定云端为零，写入失败保留待交分数；主动刷新可重试，没有无限重试。主域提交回调表示本机或消息已排队，不等于云写入成功。

朋友昵称、头像、openid 与名单仅在开放数据域处理，主域只绘制共享画布，不以像素编码或其他形式回传朋友数据。进度、残局、库存、经验、打卡、设置、本地昵称、头像与外观在设备保存，云排行成绩不会恢复这些数据。本地个人资料不替代微信朋友榜的真实昵称与头像。

微信托管 API 未提供本工程使用的事务比较并交换能力，不能保证不同设备同时写入的原子合并；客户端积分也没有接入自建评分服务器校验。

## 微信后台与实际验收

在公众平台《用户隐私保护指引》中声明“微信朋友关系”。官方把朋友读取、开放域本人读取与托管写入均列为该项；未声明或未完成隐私授权，接口会失败。本工程实现自定义隐私弹层及 SDK 的展示、同意、拒绝事件，指引由 `wx.openPrivacyContract` 打开。

无需臆测添加 `game.json.permission.scope.WxFriendInteraction.desc`；朋友权限由对应授权 API 处理。后台隐私配置尚未由本次操作提交。

真实朋友数据尚未联机验收：需要微信开发者工具和两名有微信朋友关系的用户，使用同一 AppID 的体验版，完成普通关卡、托管并授权后查看。还需核对客户端的隐私说明、拒绝授权、网络失败与重新打开。

本次实现游戏内排行榜，不代表已在微信小游戏中心配置系统榜，也没有完成上传、审核或发布。自动测试只证明源码及模拟接口行为，日志随工程交付。

## 数据使用说明草稿

排行榜经允许后，将本人累计普通关卡最高积分、通关数和累计最佳活动耗时保存至微信小游戏托管服务，用于朋友排名。开放数据域读取同游戏朋友的昵称、头像和成绩，仅绘制榜单，不上传到自建服务器。

游戏进度、残局、教学标记、最佳积分与用时、道具、经验、打卡、个人资料和设置在设备保存。当前不读取手机号、位置或通讯录，不调用广告或支付。运营主体、联系渠道及后台指引按真实账号资料填写。
